# 設計境界ガード

## 1. このドキュメントの対象

このドキュメントでは、主に次のテストを扱う。

```text
main/tests/Architecture.Tests.ps1
main/tests/LastMonthInstallExtract.Architecture.Tests.ps1
main/tests/Dom.OperationRegistryContract.Tests.ps1
main/tests/Foundation.PublicApi.Tests.ps1
```

これらは単体機能のテストというより、**設計の破壊を検出するためのテスト**である。

## 2. Architecture.Tests.ps1 が守るもの

`Architecture.Tests.ps1` は、このプロジェクトの最重要ガードである。

このテストは、ファイルの中身を文字列として走査し、禁止パターンが混入していないかを確認する。

代表的な禁止対象は以下である。

| 禁止対象 | なぜ禁止するか |
|---|---|
| `Invoke-WebRequest` | Feature側がChrome/CDP通信を直接持つとFoundation基盤を迂回するため |
| `ClientWebSocket` / `System.Net.WebSockets` | WebSocket通信はFoundation低レベル通信層に閉じるべきため |
| `Send-CDPCommand` / `Invoke-CDPJS` など | Feature moduleがCDP詳細に依存するため |
| `Import-Csv` / `Export-Csv` / `Get-ChildItem` など | Workflowが直接I/Oを持つとテスト差し替えが難しくなるため |
| `Get-Date` / `Start-Sleep` | 時刻やsleepはTiming port経由にすべきため |
| `Invoke-FoundationDomHelperMethod` | Feature側のraw DOM helper呼び出しはDomOperationsに閉じるべきため |

## 3. Workflowに書いてはいけないもの

Feature moduleのWorkflowは、処理順序を表す場所である。

そのため、次のような具体的な外部依存を書いてはいけない。

```powershell
Get-Date
Start-Sleep
Import-Csv
Export-Csv
Invoke-WebRequest
ClientWebSocket
Invoke-FoundationDomHelperMethod
```

Workflowが必要とする外部依存は、`Dependencies.ps1` で作られたportを通して受け取る。

正しい方向は次である。

```text
Workflow
  ↓
Dependencies / Port
  ↓
DomAdapter / Input / Output / Download / FileSystem / Timing
  ↓
Foundation or OS / Browser
```

## 4. DomOperationsだけがraw DOM helperを呼ぶ理由

PowerShell側からJavaScript DOM helperを呼ぶ入口は `Invoke-FoundationDomHelperMethod` などである。

しかし、これをWorkflowやRowActionから直接呼ぶと、次の問題が起きる。

```text
1. WorkflowにJavaScript method名が漏れる
2. 業務処理とDOM実装名が結合する
3. MissingHelperBehaviorやAwaitなどの契約設定が呼び出し元に散らばる
4. JavaScript側のmethod名変更の影響が広がる
```

そのため、raw DOM helper呼び出しは各Feature moduleの `DomOperations.ps1` に閉じる。

```text
Workflow / RowAction
  ↓ 業務名の関数
DomAdapter.ps1
  ↓ operation名
DomOperations.ps1
  ↓ MethodName
Foundation DomHelper
  ↓ JavaScript
window.__XxxDomHelper.methodName()
```

## 5. InstalledAppExport RowActionの特別扱い

`InstalledAppExport/internal/RowAction.ps1` は比較的大きい。  
しかし、このプロジェクトでは、単純に「大きい関数だから分割する」とは判断しない。

RowActionは、1台分のアプリCSV取得を1つの業務トランザクションとして扱う。

```text
行を開く
詳細パネルを確認する
アプリタブを開く
CSVを出す
ダウンロードを待つ
リネームする
詳細パネルを閉じる
```

`Architecture.Tests.ps1` は、RowActionが `DomOperations.ps1` を直接呼ばず、`DomAdapter.ps1` の業務名関数を呼ぶことを守っている。

これは「RowActionは大きくてもよいが、DOM helperの詳細を持ってはいけない」という境界である。

## 6. ScanTargetSync policy files の純粋性

次のファイルはPolicy層として扱われる。

```text
modules/ScanTargetSync/internal/CsvInput.ps1
modules/ScanTargetSync/internal/Rules.ps1
modules/ScanTargetSync/internal/Reconciliation.ps1
```

ここに書いてよいのは、入力データの解釈、判定、突き合わせである。

書いてはいけないものは次である。

```text
ブラウザ操作
CDP操作
DOM helper呼び出し
直接ファイルI/O
直接時刻取得
sleep
console出力
```

これにより、CSV判定や突き合わせはブラウザなしでテストできる。

## 7. Dom.OperationRegistryContract.Tests.ps1 が守るもの

このテストは、PowerShell側 `DomOperations.ps1` と JavaScript側DOM bundleの対応を確認する。

守っている契約は次である。

```text
PowerShell operation定義の MethodName
  ↓
DOM JavaScript bundle内に同名methodが存在する
```

例えば、PowerShell側で次のようなoperationがあるとする。

```text
Operation = ClickExportMenuItem
MethodName = clickExportMenuItem
```

この場合、JavaScript側の `window.__DeviceListExportDomHelper` に `clickExportMenuItem` が実装されていなければならない。

このテストが落ちる典型例は以下である。

```text
DomOperations.ps1 の MethodName を変更したが JS側を変えていない
JS側のmethod名を変更したが PowerShell側を変えていない
foundation.jobs.psd1 の DomFeaturePaths から必要JSファイルを外した
index.jsでwindow.__XxxFoundation登録を変えた
```

## 8. Foundation.PublicApi.Tests.ps1 が守るもの

Foundationモジュールは内部関数を大量に持つ。  
しかし、外部に公開してよい関数は限定される。

`Foundation.PublicApi.Tests.ps1` は、Foundationがサポート対象の公開APIだけをexportしていることを確認する。

このテストが落ちる場合、次のどちらかを疑う。

```text
1. 内部関数を不用意にExport-ModuleMemberした
2. Feature moduleから使うべき公開関数をexportし忘れた
```

内部関数を公開すると、Feature moduleが低レベル実装に依存しやすくなる。  
したがって、このテストはDIP境界の一部である。

## 9. LastMonthInstallExtract.Architecture.Tests.ps1 が守るもの

LastMonthInstallExtractはDOMを使わないCSV処理ジョブである。  
そのため、DOM/CDPへの依存が混入すると設計として不自然である。

このテストは、LastMonthInstallExtractのWorkflow、Runner、Policyファイルに以下が混入しないことを守る。

```text
直接I/O
直接時刻取得
DOM
CDP
console
sleep
```

LastMonthInstallExtractの処理はファイル処理であるが、それでもWorkflowが直接 `Get-ChildItem` や `Export-Csv` を持たないようにしている。  
理由は、Input / Output / Dependenciesの境界を守るためである。
