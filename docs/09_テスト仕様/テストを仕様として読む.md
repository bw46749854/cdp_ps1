# テストを仕様として読む

## この文書の位置づけ

この文書は横断ガイドです。
テストファイルごとの詳細仕様やテストケース一覧の正本ではありません。

目的は、テストを単なる動作確認ではなく、設計境界を守る仕様として読むための観点を示すことです。

## まず理解すること

このプロジェクトでは、テストは次の2種類の意味を持ちます。

| 種別 | 役割 |
|---|---|
| 単体テスト | 関数・部品の振る舞いを固定する |
| Architecture test | 依存方向、責務境界、禁止呼び出しを固定する |

特に `tests/Architecture.Tests.ps1` は、設計境界のガードです。
テストが落ちた場合、単に期待値を直すのではなく、何の境界を守っているかを先に確認してください。

## 誤解しやすい点

- テストは「実装に合わせて直すもの」ではありません。守っている設計意図を確認してから変更します。
- Architecture test は、過剰リファクタリングを防ぐ役割も持ちます。
- DOM operation contract test は、PowerShell側のoperation registryとJavaScript helperの対応を守ります。
- テストファイル一覧を手で保守する場合、実ファイルとのズレが起きやすいため、品質ゲートで検出する対象にします。

## 変更内容別の参照先

| 変更内容 | 参照先 |
|---|---|
| SRP / DIP / 依存方向 | `Architecture.Tests.ps1`, `main/ARCHITECTURE.md` |
| DOM operation の追加・変更 | `Dom.OperationRegistryContract.Tests.ps1`, DOM JS tests |
| Feature別の業務ルール変更 | 該当Featureの `*.Tests.ps1` |
| JavaScript DOM helper変更 | `tests/js/*.test.js`, `docs/08_DOM_JavaScript/**/*.md` |
| docsとテスト一覧の整合 | `docs/09_テスト仕様/06_テストファイル一覧.md` |
| source-doc対応や廃止参照の検出 | `docs/09_テスト仕様/07_ドキュメント品質ゲート.md`, `Documentation.Tests.ps1` |

## この文書を更新する条件

テスト群の分類、読む順番、テストが守る設計境界、変更内容別の参照先が変わった場合に更新します。
個別テストケースの詳細は、対応する個別テスト仕様ドキュメントまたはテストファイルを更新してください。
