# ドキュメント品質ゲート

## この文書の位置づけ

この文書は、`main/tests/Documentation.Tests.ps1` の読み方を説明します。
目的は、ドキュメントの更新漏れ、存在しない参照、実装とdocsの不一致を、人間の記憶ではなくテストで検出することです。

ドキュメントは保守判断の入口になります。source と docs がズレると、古いdocsを信じて誤った変更を行う危険があります。そのため、この品質ゲートは「docsが存在するか」だけでなく、起動入口やDOM operationのような重要な対応関係も確認します。

---

## 品質ゲートで守ること

現行の品質ゲートでは、最低限次を確認します。

| チェック | 目的 |
|---|---|
| production source に対応する個別ドキュメントが存在する | sourceだけ増えてdocsが無い状態を防ぐ |
| 存在しない旧ファイル名参照がliving docsに残っていない | 廃止済み設計を正本に見せない |
| `ARCHITECTURE.md` の maintenance guide path が実在パスを向いている | 重要文書の導線切れを防ぐ |
| ScanTargetSync DOM operation registry と docs のoperation名が一致する | `Await` や helper契約の説明漏れを防ぐ |
| テストファイル一覧が現行test fileを含む | テスト仕様docsの古さを検出する |
| living docs 内のバッククォート付き `docs/...` / `main/...` 参照が実在する | 読む順番や詳細参照の導線切れを防ぐ |
| `docs/10_SOLID原則/抽象の価値判断.md` が第二の設計正本になっていない | `ARCHITECTURE.md` との将来乖離を防ぐ |
| root `.bat` と `docs/01_起動設定/bat起動入口とJobName.md` の `JobName` が一致する | 利用者入口の説明劣化を防ぐ |
| `.bat` の `JobName` が `foundation.jobs.psd1` に存在する | 存在しないジョブを起動する入口を防ぐ |
| 週次 `.bat` を `ScanTargetSync` 単体実行として説明していない | Composite Job の誤説明を再発させない |
| `foundation.jobs.psd1` の `JobName` / `ModulePath` / `CommandName` と起動設定docsが一致する | Job registry の説明劣化を防ぐ |
| `UsesDom = $false` / `DomFeaturePaths` が起動設定docsに反映されている | DOM使用有無の誤解を防ぐ |
| 全 Feature の `DomOperations.ps1` と `PowerShell_DOM対応表.md` が一致する | PowerShell operation と JS method の対応漏れを防ぐ |
| `DOM契約とselector診断の読み方.md` が主要入口docsから参照されている | DOM契約の基礎説明が孤立することを防ぐ |

## production source と docs の対応

対応ルールは次です。

| source | docs |
|---|---|
| `main/run_job.ps1` | `docs/01_起動設定/run_job.ps1.md` |
| `main/config/*.psd1` | `docs/01_起動設定/config__*.psd1.md` |
| `main/modules/<Module>/<Module>.psm1` | `docs/<Module対応フォルダ>/<Module>.psm1.md` |
| `main/modules/<Module>/internal/*.ps1` | `docs/<Module対応フォルダ>/internal__*.ps1.md` |
| `main/dom/features/<feature>/*.js` | `docs/08_DOM_JavaScript/<feature>/*.js.md` |

root の `.bat` は production source の個別docs対応には含めません。代わりに、起動入口の対応関係として `docs/01_起動設定/bat起動入口とJobName.md` と照合します。

## `.bat` と `JobName` の品質ゲート

root の `.bat` は利用者が最初に触る入口です。ここがdocsとズレると、実行されるジョブの理解が根本から崩れます。

この品質ゲートでは次を確認します。

```text
1. root の *.bat から -JobName を抽出する
2. 抽出した JobName が main/config/foundation.jobs.psd1 に存在する
3. docs/01_起動設定/bat起動入口とJobName.md に .bat ファイル名が載っている
4. 同じdocsに JobName が載っている
5. 週次 .bat を ScanTargetSync 単体実行として説明する古い記述が残っていない
```

この検査により、`.bat` の変更、JobNameの変更、docsの更新漏れを検出します。

---

## `foundation.jobs.psd1` と起動設定docsの品質ゲート

`foundation.jobs.psd1` は、`JobName` を実装へ変換するジョブレジストリです。ここでは次を確認します。

```text
- 各 JobName が docs/01_起動設定/config__foundation.jobs.psd1.md に載っている
- 各 ModulePath が同じdocsに載っている
- 各 CommandName が同じdocsに載っている
- UsesDom = $false のJobは、docsの表でも UsesDom = $false と説明されている
- DomFeaturePaths を持つJobは、docsの表でも DomFeaturePaths と説明されている
```

実行時設定値は `foundation.config.psd1` 側の責務です。`foundation.jobs.psd1` の品質ゲートでは、DownloadDirectory や DaysThreshold などは確認しません。

---

## DOM operation 対応表の品質ゲート

DOM operation は、PowerShell側とJavaScript側をつなぐ契約です。

検査対象は次です。

```text
main/modules/DeviceListExport/internal/DomOperations.ps1
main/modules/InstalledAppExport/internal/DomOperations.ps1
main/modules/ScanTargetSync/internal/DomOperations.ps1
docs/08_DOM_JavaScript/PowerShell_DOM対応表.md
```

確認する項目は次です。

```text
- HelperName
- PowerShell operation 名
- JavaScript MethodName
- MissingHelperBehavior
- ContractScope がある場合はその値
- Await = $true がある場合はその値
```

この検査により、PowerShell側に operation を追加したのに対応表へ書き忘れた、method名を変えたのにdocsが古い、`Await = $true` の意味契約を説明していない、といった劣化を検出します。

## 変更時の使い方

source fileを追加した場合は、対応する個別ドキュメントも追加してください。

DOM operationを追加した場合は、次を同時に確認してください。

```text
- PowerShell側 DomOperations.ps1
- JavaScript側 method
- tests/js/*.test.js
- *.DomOperations.Tests.ps1
- Dom.OperationRegistryContract.Tests.ps1
- docs/08_DOM_JavaScript/PowerShell_DOM対応表.md
- 対応する個別DOM JavaScript docs
```

root `.bat` を変更した場合は、次を同時に確認してください。

```text
- .bat 内の -JobName
- main/config/foundation.jobs.psd1
- docs/01_起動設定/bat起動入口とJobName.md
- docs/00_最初に読む/03_JobNameとContextの関係.md
```
